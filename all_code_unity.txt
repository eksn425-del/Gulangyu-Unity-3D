1. 项目定位
本仓库是“听见·鼓浪屿”项目的 Unity 3D 数字孪生与仿真端，承担的不是通用 Web 业务，而是以下几类能力：
- 场景化还原鼓浪屿局部建筑与道路环境
- 视障通行交互模拟
- 盲杖式空间探测与 3D 声音反馈
- 危险触发采样与风险数据上报
- A/B 路线实验代理运行与自动汇总

它与主业务仓库 e:\my-gulangyu 的关系是：
- Unity 负责 3D 场景、代理、碰撞、探测、仿真
- Web/Backend 负责数据库、AI、路径算法、看板与汇总接口

5. 核心脚本当前实现
================================================================================
5.1 PlayerController.cs
职责：
- 手动移动控制
- 自动导航模式开关
- 与 NavMeshAgent / Rigidbody 协同

当前实现特点：
- FixedUpdate() 中读取 Horizontal / Vertical 输入
- 通过 rb.velocity 写入位移
- autoNavMode 为 true 时跳过手动输入
- SetDestination() 可给 NavMeshAgent 设置目标点

它是角色移动基础，不负责风险判断，也不负责上报。

5.2 DigitalCane.cs
这是 Unity 端最关键的感知脚本之一。

当前职责：
- 正前方射线探测
- 斜下方跌落探测
- 冷却节流
- 根据 hazard 类型播放 3D 空间音频
- 向后端发送 JSON 风险日志
- 记录当前 Agent 的 hazardTriggerCount

当前可识别/触发的主要 hazard 类型包括：
- Stairs
- Road_Stone
- Road_Cement
- Drop-off

当前重要字段包括：
- forwardRayLength
- downwardRayLength
- downwardRayOriginOffset
- backendUrl
- agentGroup
- cooldownTime
- enableForwardHazardScan
- enableDropOffScan
- minAudioDistance
- maxAudioDistance

当前数据上报结构为 HazardData：
- x
- y
- z
- obstacle_type
- client_source

这意味着 Unity 上报的数据不仅有危险类型，也带有坐标和来源分组。

5.3 HazardZone.cs
这是场景内主动标记危险区域的脚本。

当前职责：
- 在 OnTriggerEnter 时识别进入区域的对象
- 向其父对象上的 DigitalCane 发送 ReportHazard()
- 通过 reentryCooldown 避免同一代理重复刷同一区域

当前用途非常明确：
- 把“场景设计的高风险区域”转化成可统计的 hazard 事件
- 为 A/B 路线实验制造可量化差异

5.4 RouteFollower.cs
这是 Unity 端与主业务后端路径算法对接的桥梁。

当前流程：
1) StartRoute(startNodeId, endNodeId)
2) GET 请求主后端 /api/route
3) 读取 routes[0].steps[].to_name
4) 在场景中按名称查找同名 Transform
5) 逐个 waypoint 驱动 NavMeshAgent 导航
6) 若失败则回退到 fallbackTarget 或 fallbackDestination

当前关键状态：
- HasBegunNavigation

这个状态被 ABTestController 用来避免“路线还没取回来就被误判为已到达”。

5.5 ABTestController.cs
这是 Unity 端 A/B 实验总控器。

当前职责：
- 批量生成 group_A 与 group_B 代理
- 给代理绑定分组名
- 可统一覆盖 DigitalCane 的扫描配置
- group_B 可接后端 safest/shortest 路线
- 按运行期统计：
  - agent 数量
  - 触发过 hazard 的代理数量
  - 平均路径长度
  - 平均完成时间
- 自动把汇总结果 POST 到 /api/ab_test_summary

当前关键配置字段包括：
- groupACount / groupBCount
- groupASpeed / groupBSpeed
- abSummaryUrl
- summaryClientSource
- useBackendRouteForGroupB
- groupBRouteApiBaseUrl
- bGroupStartNodeId / bGroupEndNodeId
- groupBUserType
- groupBStrategy
- overrideDigitalCaneScanSettings
- enableForwardHazardScanForABAgents
- enableDropOffScanForABAgents

当前汇总 payload 结构：
- test_run_id
- total_agents
- group_a
- group_b
- client_source

5.6 BuildingInteraction.cs
职责简单：
- 当带有 Player 标签的对象与建筑碰撞时输出日志

它主要用于场景交互验证，不参与主数据闭环。

6. Unity 内置 Backend 的定位
================================================================================
6.1 Backend/main.py
当前仅提供：
- POST /api/record_hazard

当前行为：
- 接收 x、y、z、obstacle_type
- 记录到 accident_logs.csv
- 控制台打印危险日志

6.2 Backend 的实际定位
这个 Backend 不是整个项目的主业务后端，只是 Unity 仓库里的本地轻量记录端。

与 e:\my-gulangyu\backend 相比，它缺少：
- SQLite 业务库
- AI 对话
- 路径规划
- A/B 汇总接口
- 管理后台接口
- 热力图 API

因此它更像：
- 本地实验后端
- 早期采样后端
- 离线分析辅助端

7. 当前网络对接关系
================================================================================
脚本中默认对接的主后端地址为：
- DigitalCane.backendUrl -> http://127.0.0.1:8000/api/record_hazard
- ABTestController.abSummaryUrl -> http://127.0.0.1:8000/api/ab_test_summary
- ABTestController.groupBRouteApiBaseUrl -> http://127.0.0.1:8000
- RouteFollower.routeApiBaseUrl -> http://127.0.0.1:8000

因此 Unity 当前并不是孤立运行，而是默认设计为与主业务后端同机联调。

8. 当前 A/B 实验机制
================================================================================
8.1 分组机制
- group_A：通常使用普通目标点导航
- group_B：可使用 RouteFollower 从主后端拉取 safer 路线

8.2 指标机制
Unity 当前能直接产生的实验指标包括：
- agent_count
- hazard_exposed_agent_count（至少触发一次危险提示的代理数）
- avg_path_length
- avg_completion_time

8.3 实验运行链路
1) StartABTest()
2) 生成 A/B 代理
3) 代理行走
4) DigitalCane / HazardZone 触发 hazard
5) 统计每个代理路径长度与完成时间
6) 聚合为 group_a / group_b 指标
7) POST 到主业务后端

8.4 当前实验意义
Unity 端承担的不是“把 A/B 结果展示出来”，而是“生成可量化的 A/B 原始行为数据”。
结果展示发生在 Web 仓库的策展看板中。
近期已完成 10+ 代理规模的多轮实验（10v10、12v12、15v15），数据已可用于论文统计。

10. 当前代码状态的关键事实
================================================================================
- Unity 的主要业务价值已经从“单机场景演示”扩展到了“主后端联动实验端”
- RouteFollower 说明 Unity 已经开始消费主后端算法，不再是纯本地逻辑
- ABTestController 说明 Unity 已具备自动实验能力，而不是只能手工试玩
- DigitalCane 当前既负责本地声反馈，也负责云端数据回传
- Unity 仓库内的 Backend 仍然存在，但它不是当前整个系统的唯一真实后端
- SampleScene 与 NavMesh 资产近期有联调更新，配合 A/B 重复实验参数调优

================================================================================
11. 与主业务仓库的接口关系
================================================================================
当前 Unity -> Web/Backend 的主要对接接口有：
- /api/record_hazard
- /api/ab_test_summary
- /api/route

数据流关系为：
- Unity 上报 hazard 给主后端
- Unity 请求 safest 路线自主管理代理导航
- Unity 把 A/B 汇总交给主后端入库
- 主后端再把这些数据展示到 Web 看板
