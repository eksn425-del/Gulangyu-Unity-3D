1. 项目定位与边界
本项目是 Unity 端数字孪生与交互仿真客户端，重点在“视障通行体验模拟 + 风险探测上报 + 空间音频反馈”。
它并不承载完整导览业务后端，主业务后端在独立仓库 e:\my-gulangyu\backend。
当前 e:\Gulangyu_3D\Backend 属于 Unity 项目的本地后端备份与实验链路。

3. 入口、依赖与关键配置
================================================================================
3.1 场景入口与挂载关系
- 构建入口场景：Assets/Scenes/SampleScene.unity（EditorBuildSettings 当前启用该场景）。
- 场景中玩家对象（Capsule，Tag=Player）挂载：
  - PlayerController（移动）
  - DigitalCane（探测与上报）

3.2 引擎与依赖
- Unity Editor 版本：2022.3.62f3c1
- 渲染管线：URP（com.unity.render-pipelines.universal 14.0.12）
- 常用包：TextMeshPro、Timeline、UGUI、VisualScripting、Test Framework 等（详见 Packages/manifest.json）

3.3 网络配置（高优先级）
- DigitalCane.cs 代码默认 backendUrl：
  http://127.0.0.1:8000/api/record_hazard
- ABTestController 汇总上报地址：
  http://127.0.0.1:8000/api/ab_test_summary
- RouteFollower 取路地址基于：
  http://127.0.0.1:8000/api/route
- 测试前需确认后端已启动，否则会在 Console 出现
  Cannot connect to destination host。

3.4 Tag 配置现状
- TagManager 现有业务相关 Tag：Stairs、Road_Stone
- DigitalCane 脚本同时会识别：Stairs、Road_Stone、Road_Cement
- 结论：若要触发 Road_Cement 逻辑，需在 TagManager 中补充该 Tag 并赋给对应Collider。

4. 核心模块与可追溯业务流
================================================================================
4.1 PlayerController.cs（移动控制）
- 入口：FixedUpdate()
- 行为：读取 Horizontal/Vertical 输入，计算 moveDirection，写入 rb.velocity。
- 作用：确保角色在物理系统内稳定移动，供盲杖探测使用真实位置与朝向。

4.2 DigitalCane.cs（核心探测与反馈）
- 数据模型：HazardData { x, y, z, obstacle_type }
- 生命周期：
  1) Start() 初始化 tagAudioMap（标签->音频）
  2) Update() 执行双射线探测
     - 前向射线：识别台阶/路面障碍
     - 下向射线：未命中地面判定为 Drop-off
  3) TryTriggerHazard() 冷却节流（cooldownTime）
  4) PlaySpatialAudio() 在碰撞点创建临时AudioSource进行3D播放
  5) PostHazardData() 用 UnityWebRequest 发送 JSON POST
- 关键参数：
  - forwardRayLength, downwardRayLength, cooldownTime
  - minAudioDistance, maxAudioDistance
  - backendUrl
- 当前新增实验开关：
  - enableForwardHazardScan
  - enableDropOffScan
- 作用：A/B 实验时可关闭 Drop-off 自动上报，避免统一噪声淹没路径安全差异

4.3 HazardZone.cs（场景风险触发）
- 入口：OnTriggerEnter(Collider other)
- 行为：识别进入触发区的 Agent，按 hazardType 调用 DigitalCane.ReportHazard()
- 特性：内置 reentryCooldown，避免同一 Agent 在短时间内重复刷同一危险区
- 作用：用于按场景布局人为设计 A/B 风险差异，是当前实验区分 A/B 安全性的主要手段

4.4 RouteFollower.cs（后端路径跟随）
- 入口：StartRoute(startNodeId, endNodeId)
- 行为：请求主后端 /api/route，读取 steps[].to_name，按场景同名 Route Marker 逐点导航
- 关键状态：HasBegunNavigation，用于防止 ABTestController 在异步取路前误判“已到达”
- 失败兜底：若取路失败或缺少 marker，则自动回退到 fallbackTarget

4.5 BuildingInteraction.cs（辅助日志）
- 入口：OnCollisionEnter(Collision collision)
- 行为：与 Player 碰撞时输出建筑命中日志。
- 作用：用于快速场景交互验证，不参与风险上报主链。

4.6 ABTestController.cs（A/B 自动化主控）
- StartABTest()：按组生成 Agent_A/Agent_B，并分配 group_A/group_B。
- RunAndSubmitSummary()：统计完成时长、路径长度、hazard 触发次数。
- PostSummary()：POST 到 /api/ab_test_summary。
- 当前能力补充：
  - group_B 可通过 RouteFollower 使用主后端 safest 路线
  - overrideDigitalCaneScanSettings 可统一覆盖 A/B Agent 的 DigitalCane 开关
  - enableDropOffScanForABAgents 默认可关闭，便于纯观察 HazardZone 带来的风险差异

4.7 Backend/main.py（Unity本地后端）
- 提供 /api/record_hazard
- 请求体字段：x, y, z, obstacle_type
- 行为：写入 accident_logs.csv

4.8 Backend/data_analysis.py（离线分析）
- 读取 accident_logs.csv
- 统计高频碰撞区域并输出 collision_heatmap.png

端到端业务流：
玩家输入 -> PlayerController移动 -> DigitalCane射线命中/落空 ->
TryTriggerHazard -> 播放3D音频 -> POST风险数据 -> Backend写CSV ->
data_analysis.py 生成热力图

A/B 实验业务流：
ABTestController 生成 group_A/group_B -> group_B 通过 RouteFollower 调用主后端 /api/route ->
Agent 按路径行走并统计 pathLength/completionTime -> HazardZone/DigitalCane 上报 hazard ->
ABTestController 汇总 POST /api/ab_test_summary -> Web Dashboard 拉取 latest/history 展示

5. 运行与测试前检查清单（含 A/B）
================================================================================
1) 后端可用：
   - 若接 Unity 内置后端：先启动 e:\Gulangyu_3D\Backend\main.py
   - 若接主业务后端：先启动 e:\my-gulangyu\backend\main.py
2) 接口地址一致：
   - 检查 SampleScene 中 DigitalCane.backendUrl 与目标后端接口一致
   - 检查 ABTestController.abSummaryUrl、groupBRouteApiBaseUrl 是否指向主业务后端
3) Tag 完整：
   - 至少保证 Stairs、Road_Stone 可用
   - 需要 Road_Cement 时补Tag与Collider
4) 音频资源绑定：
   - audioStairs/audioDropOff/audioRoadStone/audioRoadCement/audioDefault 非空
5) 场景对象：
   - Player 挂载 Rigidbody + PlayerController + DigitalCane
   - ABTestRoot 挂载 ABTestController，并配置 Agent_A/Agent_B prefab 与 Spawn/Target 点位
   - group_B 路线依赖场景中与后端 steps.to_name 同名的 Route Marker
6) AudioListener 唯一性：
   - 场景中仅保留 Main Camera 一个 AudioListener
7) Play 验收：
   - Console 出现 summary submit success 代表 A/B 汇总链路打通
8) 当前推荐实验口径：
   - overrideDigitalCaneScanSettings = true
   - enableForwardHazardScanForABAgents = true
   - enableDropOffScanForABAgents = false
   - 这样可优先观察 HazardZone 与路线差异，而不是被 Drop-off 噪声覆盖

6. AI 接手修改准则（避免误改）
================================================================================
1) 改探测规则、冷却、上报字段：只改 Assets/Scripts/DigitalCane.cs
2) 改角色运动：只改 Assets/Scripts/PlayerController.cs
3) 改后端取路与 marker 跟随：只改 Assets/Scripts/RouteFollower.cs
4) 改场景危险区触发：只改 Assets/Scripts/HazardZone.cs，并同步检查 Collider Is Trigger
5) 改 A/B 运行逻辑与汇总：只改 Assets/Scripts/ABTestController.cs
6) 改构建入口场景：改 ProjectSettings/EditorBuildSettings.asset
7) 改后端接收协议：同步 Unity 端 HazardData 与后端接口字段
8) 改标签策略：同时修改 TagManager 与模型Collider标签
