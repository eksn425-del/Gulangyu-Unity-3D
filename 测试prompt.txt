## 七、当前主要短板

**最脆弱的部分（按危险程度排序）**：

1. **单终点导航场景 0% 准确率**——这是用户最高频的使用场景（"我要去XX"），全部失败。根本原因：`infer_start_end_from_semantics` 要求 `mentioned_nodes >= 2` 才设置 end_node，单地点时 end_node 永远是 null
2. **平均延迟650ms**——SOP要求100ms，差距6.5倍，演示时用户等待感明显（注意：test_mode算法层本身20-50ms正常，问题出在LLM调用）
3. **RouteFollower的Route Marker依赖**——若场景中没有与后端节点名完全匹配的GameObject，B组全部fallback，实验有效性存疑
4. **本地图片资源缺失风险**——演示时若 `/static/images/` 路径下没有对应图片，页面展示降级严重

---

## 八、下一步优先事项

**按紧迫程度，最应该先做这3件事**：

**第1件（最紧迫）：修复单终点导航bug**

在 `main.py` 的 `chat` 接口中，将 `infer_start_end_from_semantics` 的条件从 `>= 2` 改为支持单节点提取终点：

```python
# 现状（有bug）
if navigation_intent and len(mentioned_nodes) >= 2:
    start_node, end_node = infer_start_end_from_semantics(...)

# 修复方向
elif navigation_intent and len(mentioned_nodes) == 1:
    end_node = mentioned_nodes[0]["node"]
    # matched_end_place 应赋值，而非保持 null
```

这个修复能把准确率从77.5%提升到预计88%+，直接满足SOP验收标准。

**第2件（演示前必做）：准备本地静态资源包**

确认 `backend/static/images/` 下有 `home_header.jpg`、`routing_comparison.png`，以及7个建筑的图片文件。当前代码在 `onError` 时 fallback 到 Unsplash，网络不稳定时演示会出现白图。

**第3件（学术价值）：补一张完整的实验结论图表**

在前端 Landing Page 或 Unity 录屏中，将 A组危险率1.0 vs B组危险率0.0 的对比用一张可视化图（已有 `BarChart`）固化下来，配上路径长度数据，形成完整的"系统有效性验证结论"——这是向导师/评委介绍时最核心的一张图。
